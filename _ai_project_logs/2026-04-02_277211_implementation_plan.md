# 팀원 개발 내용 통합(Merge) 및 챗봇 연동 테스트 계획서

다른 팀원들이 제작한 페이지(메인 페이지, 정보 추가 등)를 현재 내 로컬 환경에 반영하여, 챗봇이 모든 페이지에서 유기적으로 작동하는지 확인합니다.

## User Review Required

> [!IMPORTANT]
> **병합(Merge) 전 주의사항**
> - 현재 작업 중인 파일들이 모두 저장 및 커밋(Commit)되어 있어야 합니다.
> - 병합 과정에서 동일한 파일을 수정한 경우 **충돌(Conflict)**이 발생할 수 있으며, 이 경우 수동으로 코드를 정리해야 합니다.

## Proposed Changes

### 1. 최신 코드 분석 및 가져오기 (Git Fetch)
원격 저장소의 모든 브랜치 상태를 가져옵니다. 
- `origin/dev`: 팀장님의 베이스라인 및 공통 작업 (현재 로컬에 없는 Customer, Reservation 관련 JSP 대거 포함)
- `origin/feature/*`: 팀원별(Yuri, Dohui, Seok) 개별 작업물

### 2. 단계적 브랜치 통합 (Merge Strategy)
단순 `dev` 병합이 아닌, 팀장님의 코드를 베이스로 하여 팀원들의 작업물을 선택적으로 합칩니다.
1. `origin/dev` 병합: 프로젝트의 전체적인 골격(JSP 페이지들)을 로컬에 반영합니다.
2. 각 팀원 브랜치 병합: 개별적으로 개발되어 아직 `dev`에 합쳐지지 않은 페이지들을 가져옵니다.
    - *주의*: 유리(Yuri)님의 브랜치처럼 `templates/index.html` (Thymeleaf) 형식을 사용하는 경우 현재의 JSP 기반 챗봇 연동과 충돌이 발생할 수 있으므로 조율이 필요합니다.

### 3. 챗봇 연동 확인
- 팀원들이 만든 새 페이지들(`index.jsp` 등)에 `chatbot.jsp`가 공통적으로 포함되어 있는지 확인합니다.
- 만약 공통 `footer` 등을 사용하지 않아 챗봇이 누락된 페이지가 있다면, 해당 파일들에 인클루드 코드를 추가합니다.

### 4. 로컬 서버 검증
서버를 재시작하여 새로운 페이지들에서 챗봇의 **페이지 인식 기능**과 **디자인**이 자연스럽게 적용되는지 테스트합니다.
